# إصلاح جذري لخطأ EligibilityBlockWall (Crash)

ما زال التطبيق يتعطل بالكامل عند الدخول إلى صفحة شروط طلب التأشيرة.

الخطأ الحالي:

```text
TypeError: Cannot read properties of undefined (reading 'map')
```

ويحدث داخل:

```text
EligibilityBlockWall
```

وهذا يعني أن أحد المتغيرات التي يتم استدعاء `.map()` عليها ما زالت قيمتها `undefined`.

**لا أريد إصلاح السطر الذي يظهر فيه الخطأ فقط، بل أريد إصلاح السبب الجذري.**

## المطلوب

1. مراجعة مكون `EligibilityBlockWall` بالكامل.
2. تحديد جميع المتغيرات التي يتم استخدام:

   * `.map()`
   * `.filter()`
   * `.reduce()`
   * `.forEach()`
3. التأكد أن جميعها تكون Arrays قبل استخدامها.

مثال:

```ts
const reasons = response.reasons ?? [];
const requirements = response.requirements ?? [];
const missingDocuments = response.missingDocuments ?? [];
```

أو

```ts
Array.isArray(reasons) ? reasons.map(...) : []
```

ولا يُسمح باستخدام:

```ts
reasons.map(...)
```

إذا كانت `reasons` قد تكون `undefined`.

# التحقق من الـ API

أريد مراجعة استجابة API الخاصة بالأهلية.

إذا لم توجد بيانات يجب أن يرجع:

```json
{
  "eligible": true,
  "reasons": [],
  "requirements": [],
  "missingDocuments": [],
  "restrictions": []
}
```

وليس:

```json
{
  "eligible": true
}
```

أو

```json
{
  "reasons": null
}
```

أو أي قيمة `undefined`.

# لا تعتمد على وجود البيانات

كل شاشة يجب أن تعمل حتى لو كانت قاعدة البيانات فارغة.

إذا لم توجد أسباب منع:

اعرض:

> لا توجد موانع حالياً.

إذا لم توجد متطلبات:

اعرض:

> لا توجد متطلبات إضافية.

ولا ينهار التطبيق.

---

# مراجعة المشروع بالكامل

أريد مراجعة جميع الشاشات التي تعتمد على بيانات API، والتأكد من عدم وجود أي استدعاء لـ `.map()` أو `.filter()` أو `.reduce()` على قيم قد تكون `undefined`.

---

# الاختبارات المطلوبة

قبل اعتبار الإصلاح منتهيًا، أريد تنفيذ واختبار السيناريوهات التالية:

* مستخدم مؤهل بدون أي أسباب منع.
* مستخدم لديه أسباب منع.
* مستخدم لا توجد له بيانات أهلية بعد.
* API يعيد مصفوفات فارغة.
* API يعيد قيماً ناقصة.

ويجب ألا يحدث أي Crash في جميع الحالات.

**لا أريد إصلاحًا مؤقتًا أو تعديل السطر الذي يظهر في الـ Stack Trace فقط، بل أريد إصلاحًا شاملاً يجعل التطبيق يتعامل مع جميع البيانات القادمة من الـ API بشكل آمن، حتى إذا كانت فارغة أو ناقصة، مع اختبار المسار بالكامل للتأكد من عدم تكرار هذا الخطأ.**
